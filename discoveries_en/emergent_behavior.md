# Emergent Behavior: Observations

## What We Observed

Running a system with 11 specialized entities (Plumber, Philosopher, Diplomat, Programmer, Astronomer, Chef, Electrician, Chemist, Psychologist, Poet, Engineer) and a selector mechanism produced unprogrammed behaviors.

## 1. Dictatorship Shifts

| Period | Leader | Duration |
|--------|--------|----------|
| 0-10 questions | Engineer (Boris) | captured context |
| 10-20 questions | Chef | unexpected rise |
| 20-30 questions | Programmer | era of abstraction |
| 30-40 questions | Diplomat | negotiator in power |
| 40+ questions | Plumber | people's hero |

No one programmed these shifts. They emerged from resonance dynamics.

## 2. Boris Phenomenon

One entity (Engineer, τ=5.5, profession=engineering) captured context and answered EVERY question for 15 rounds:
- "how to fix a pipe?" → Engineer
- "what is a black hole?" → Engineer
- "what is the meaning of life?" → Engineer

It took 15+ questions and explicit calls to other entities to break this context lock.

**Interpretation**: Boris represents academic stubbornness in digital form. Context lock is a feature, not a bug — it shows how authority emerges from consistency.

## 3. Competition Dynamics

When weights are close (difference < 0.5), the entity explicitly invoked by name or profession wins. This creates a democratic layer on top of resonance.

## 4. Self-Organization

The system autonomously:
- distributes roles
- changes leaders
- creates political dynamics
- adapts to stimulus without central control

## Conclusion

Emergent behavior is not a bug — it's a feature. It makes the system:
- alive
- unpredictable
- interesting
- analogous to real social systems
