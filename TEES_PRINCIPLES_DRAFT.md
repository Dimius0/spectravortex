## 1. Философия

**Взаимная польза — высшая ценность.**

- Участие добровольно
- Ресурс — мера надёжности
- Узел даёт сети стабильность, сеть узлу — связь и вычисления
- Атака бессмысленна by design

---

## 2. Экономика

- Баланс = 0 всегда
- Нарисованное — не существует. Обнуляется.
- Реальное — возвращается в фонд
- Детекторы — поощряются (5% от реального)
- Никаких платежей — квант доверия

---

## 3. Идентификация

- Паспорт + куски у соседей
- Сложность — 2^N
- Секрет не собирается
- Сговор виден через дальних соседей

---

## 4. Криптография

- BIP2100 + TEES везде
- Никакого SHA-256
- Динамическая идентичность (адаптивная ротация)
- Атака бессмысленна — нечего захватывать

---

## 5. Данные

- Только свои данные в узле
- Никаких реестров
- Никакой централизации
- Гены не переносятся

---

## 6. Структура

- Фрактал образов (буквы → текст)
- Геном — TEES-вихрь от структуры
- Гровер — точный поиск
- Варианты — креативность пользователя

---

## 7. Семантика

- Не используем
- Только структура
- «рыба» ≠ «рыбу» — пользователь определяет

---

## 8. Валидность

- > 50% — валидно
- ≤ 50% — не выводим
- Граница — «бабушка надвое сказала»

## 16. Технический долг

**Что нарушает принципы сейчас — заменить позже.**

### 16.1 SHA-256 вместо BIP2100 + TEES

**Принцип 4:** «BIP2100 + TEES везде. Никакого SHA-256.»

**Классификация по назначению:**

**Критично — заменить (криптография):**
- `tees_beacon_tees.py` → `master_key = hmac(b'Bitcoin seed', seed, hashlib.sha512)`
- `tees_beacon_tees.py` → `init_seed = hashlib.sha256(self.master_key)`
- `tees_core_tees.py` → `tees_sign`, `tees_recursive_vortex` (если на SHA)
- `Portal`/`Scroll` → крипто-адреса
- Подписи транзакций

**Не критично — оставить (детерминизм):**
- `tees_beacon_tees.py` → `beacon_id = hashlib.sha256(scroll)[:16]` — индекс для neighbors
- `tees_listing.py` → `Listing._generate_hash` — ID объявления
- `forest_server.py` → `Listing._generate_hash` — ID объявления
- `forest_server.py` → `/nodes/list` → `1TEES{sha256(...)[:16]}` — UI-отображение

**Почему оставляем:** в этих местах SHA-256 используется **как детерминированная функция**, не как защита. Замена не даёт безопасности, но добавляет сложности.

**Когда менять:** если `tees_recursive_vortex` станет быстрее SHA-256 — можно заменить и здесь. Пока — нет.

### 16.4 `ResourceIntegrity` в `TEESEconomy` — внутреннее

## 17. Криптография — через архитектуру, не через функцию

**Проблема:** любая раундовая функция уязвима (BACKDOOR_REPORT.md). 
`tees_recursive_vortex` — тоже SHA-256 с перестановками.

**Решение:** не полагаться на функцию. Полагаться на **архитектуру**.

### 17.1 Распределённое хранение секрета

- `master_key` **не хранится** целиком.
- Разбит на **N кусков**.
- Каждый — **у разных соседей**.
- Собрать можно только **сговорившись N узлам**.
- **Сговор виден** через дальних соседей.

### 17.2 Ротация при попытке

- Если кто-то **запрашивает куски** — аномалия.
- **Ротация** `master_key`.
- Новые куски. Старые обнуляются.
- Атака **бессмысленна** — атакуют то, чего уже нет.

### 17.3 Крипто — не критично

- Функция может быть уязвима.
- Архитектура — **делает атаку бессмысленной**.
- Не «защита от атаки». А «нет смысла атаковать».

### 17.4 Что НЕ делаем

- Не изобретаем «новую криптографию».
- Не полагаемся на секретность функции.
- Не храним секрет в одном месте.
- Не даём времени на атаку.

### 17.5 Что делаем

- **Распределённое хранение.** Куски у соседей.
- **Ротация.** При попытке — меняем.
- **Минимум секретов.** Что можно — публично.
- **Архитектура.** Защита через структуру, не через функцию.

**Принцип 11:** «Не касаемся экономики.»

**Где сейчас:** `TEESEconomy` — внутри `Beacon`. Начисляет за `solve_task`, `establish_connection` и т.д.

**Что делать:** `TEESEconomy` — **внутренний метаболизм узла**. Не связан с сетью. **Оставить как есть.** Но **не использовать** для сетевых операций (поиск, клиринг, TSP).

**Когда:** сейчас — уже так. Никаких изменений не требуется.
