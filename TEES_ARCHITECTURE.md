## Введение

Проект развивается. Появилось понимание: внутри концепции симбиотического леса созревает детерминированный ИИ.

Это значит: два уровня смешаны. Пора разделить.

Цель разделения:
- стабильность (изменение в одном слое не ломает другой)
- наращивание модулей (новый модуль в свой слой)
- гибкость (ядро можно использовать отдельно)
- защищённость (ядро — детерминированное, без сетевого доступа)

## Слой первый. Ядро детерминированного ИИ

### Файлы

- tees_fractal_image.py — фрактал образов.
- tees_fractal_search.py — поиск через Гровер.
- tees_field_simulation.py — поле, шарнир, полоса срыва.
- tees_core_tees.py — вихрь, триада, геномы.
- tees_cluster.py — кубоагенты.
- tees_listing.py — варианты формулировок.

### Назначение

Чистая технология. Без метафор. Без леса. Без HTTP. Без P2P.

### Интерфейс

Python-классы. Использование в любом проекте.

### Зависимости

Только стандартная библиотека Python.

## Слой второй. Сеть

### Файлы

- tees_beacon_tees.py — маяк, P2P, поле H.

### Назначение

Транспорт. Обмен между узлами сети.

### Интерфейс

P2P-протокол. Использование в любом проекте.

### Зависимости

Ядро (для передачи фракталов). Стандартная библиотека Python.

## Слой третий. Концепция леса

### Файлы

- forest_server.py — HTTP-сервер.
- forest.html — веб-морда.
- tees_economy.py — метаболизм.
- tees_healer_tees.py — самовосстановление.
- tees_chameleon.py — маскировка.

### Назначение

Концепция. Метафора. Интерфейс для пользователя.

### Интерфейс

HTTP. Веб-морда. API.

### Зависимости

Ядро. Сеть.

---

## Интерфейсы между слоями

### Ядро и Сеть

Что передаётся: геномы фракталов. Список bytes.

Как передаётся: через heartbeat. Поле state['fractals'].

Кто вызывает: Beacon. Провайдер фракталов — callback.

### Сеть и Лес

Что передаётся: список соседей. Список str. Состояние поля H. Словарь.

Как передаётся: через прямые вызовы.

Кто вызывает: ForestServer. Прямой доступ к Beacon.

### Ядро и Лес

Что передаётся: результаты поиска. Список словарей.

Как передаётся: через прямые вызовы.

Кто вызывает: ForestServer. Прямой доступ к ядру.

## Что это даёт

### Стабильность

Изменение в слое леса не ломает ядро.
Изменение в ядре не ломает лес.
Слои независимы.

### Наращивание модулей

Новый модуль в свой слой.
Не трогает другие.
Подключается через интерфейс.

### Гибкость

Ядро можно использовать в другом проекте. Без леса.
Сеть можно использовать в другом проекте. Без ярмарки.
Лес можно переделать. Ядро — нет.

### Защищённость

Ядро — детерминированное. Никакого сетевого доступа.
Сеть — транспорт. Никакой логики.
Лес — интерфейс. Никаких секретов.

## Что это значит для TFC

TFC — метод ядра. Не метод леса.

Если ядро отдельно — TFC ложится естественно.
Если ядро внутри леса — TFC надо встраивать.

## Что это значит для роботов

TEES_ROBOTICS.md — это ядро плюс сеть. Без леса.

Робот не нуждается в ярмарке.
Робот не нуждается в HTTP.
Робот нуждается в ядре и сети.


## Порядок разделения

### Этап первый: зафиксировать интерфейсы

Документация. Без кода.

### Этап второй: вынести ядро

Создать директорию core/. Перенести туда файлы ядра.

### Этап третий: вынести сеть

Создать директорию network/. Перенести туда маяк.

### Этап четвёртый: лес как обёртка

Оставить в forest_server.py только HTTP. Подключить ядро и сеть.
